## 2. 缺陷清单（已复现）

### BUG-01【P0 严重】载入黑场里打开洞府，带着洞府进大世界：法宝复制 / 陨落不丢
- **状态**：已复现，5/5。真实界面「开始匹配」按钮路径 2/2（撤离、陨落各一次）、快速单人入口 2/2、触屏点洞府按钮 1/1；复制和「陨落不丢」各独立复现。
- **复现步骤（键鼠）**：
  1. 正常开机进主城，身上佩戴 1 件法宝。
  2. 走进「木兰草原」门 → 点关卡卡片 → 入境页点「开始匹配」。
  3. **黑场载入期间按一下 B**（触屏：载入时手指点一下右上角「洞府」圆按钮的位置）。
  4. 进入大世界后，洞府界面开着、游戏处于暂停；在「储物」页选佩戴的法宝点「取下」，关掉洞府继续玩。
  5. A：撤离成功 → 回城看仓库和佩戴；B：陨落 → 回城看仓库。
- **预期**：载入期间不能打开洞府；局内不能动存档里的仓库 / 佩戴；撤离后法宝 1 份；陨落后佩戴的法宝丢失。
- **实际**：撤离后这件法宝在仓库 1 份 + 身上 1 份（**复制**）；陨落后它还在仓库里（**陨落不丢**），而陨落结算界面仍显示「丢失法宝 1」，和实际不符。
  洞府的坊市、丹房页签在局内也一样能切过去（只看到了界面，买卖 / 炼丹没有逐一点测）。
  另外带着暂停进图，载入时间从 1.7~1.9 秒变成 11.2 秒。
- **证据**：`logs/qadupe_match_extract_out.txt`（「开始匹配」路径撤离：[1, 1]）、`logs/qadupe_match_death_out.txt`（「开始匹配」路径陨落：[1, 0]）、
  `logs/qadupe_out.txt`（陨落：[1, 0]）、`logs/qadupe2_out.txt`（撤离：[1, 1]）、
  `logs/qadupe_tap_out.txt`（触屏点按钮路径，[1, 1]）、`logs/qaflow_bload_out.txt`（暂停 = true、洞府开着 = true）、
  截图 `shots/raid_arrive_bload.jpg`（进图后洞府盖满屏幕）。
- **原因（代码定位）**：
  - `hud.gd:160` `_open_abode()` 只拦「已暂停」和「选关界面开着」；`level_select.gd:150` `_go()` 先关掉选关菜单、取消暂停才开始载入，
    而主城的洞府按钮要到 `main.gd` `_enter_level` 里 `hud.lobby = false` 才收起——中间 0.45 秒渐暗 + 匹配等待（`_matchmake` 1.6~2.6 秒）都能按 B。
  - `level_select.gd:41` 载入黑场 `ColorRect` 的 `mouse_filter = IGNORE`，点击穿透到下面的洞府按钮（手机上就是手指点一下）。
  - `raid_profile.gd:330-345` 的 `equip / unequip / sell / buy` 没有「局内（`live != null`）不许动」的保护；`end_raid`（:277）用局内那份法宝覆盖存档，
    于是局外先挪走的那份变成了额外的一份。
- **影响**：经济系统可被稳定刷取（法宝无限复制、规避「佩戴的法宝陨落即失」的核心风险），且普通玩家在载入时随手点按就可能误触；手机、桌面都受影响。
- **修复方向（供参考）**：`_open_abode` 增加 `main._switching` / 关卡存在时拒绝；载入黑场吃掉点击；`Profile` 的局外操作在 `live != null` 时一律拒绝（兜底）。

### BUG-02【P1 高】镜头没有遮挡 / 碰撞处理：主城进楼体、大世界被崖壁挡住，崖边单帧跳 37~49 米
- **状态**：已复现。主城进楼：渲染档 3/3（桌面 2 轮、手机画质档 1 轮）+ 无界面 1/1；崖壁：渲染档 3/3。
- **复现步骤**：
  1. 主城走到商店门口，朝楼里走到被墙挡住（x≈-44），转视角让镜头在楼那一侧（主角背靠楼）。仓库楼同理。
  2. 大世界找一面 ≥6 米的崖，主角背靠崖站着，把镜头从侧面扫到正后方再扫到另一侧（约 110°/秒，模拟拖视角）。
- **预期**：镜头被墙 / 崖挡时拉近或抬高到主角看得见的位置，过渡平滑。
- **实际**：
  - 主城：镜头停在 (-51.9, 2.9, -14.0)，该格实心体顶高 10 米 → 镜头在商店楼体里面，画面是楼内地板，看不到主角；仓库楼同样（实心顶高 9 米）。北面石墙没问题。
  - 大世界：崖高 40~50 米时，镜头高度在一帧之内被顶上崖顶（单帧升降 46.3 / 48.9 / 37.3 米），扫视期间 85%~92% 的帧主角被地形挡住
    （146/171、158/172、83/119 帧）。
- **证据**：`logs/qaflow_desk_out.txt`、`qaflow_bload_out.txt`、`qaflow_touch_out.txt`；截图 `shots/hub_cam_wall.jpg`（镜头在商店楼体内）、
  `shots/hub_cam_wall_仓库楼.jpg`、`shots/raid_cam_cliff.jpg` / `raid_cam_cliff_touch.jpg`（满屏崖壁，看不到主角）。
- **原因**：`camera_rig.gd:446-449` 只有「镜头不低于脚下地面 + FLOOR_GAP」一条约束，没有主角→镜头方向的遮挡检测；
  主城 `hub_hall.gd:189` 给镜头的 `floor_fn` 是不含建筑实心格（`_solid`）的地面高度。
- **影响**：方块世界到处是台阶和崖壁、主城到处是建筑，普通走动转视角就会碰到；手机上看不到主角直接影响操作。

### BUG-03【P2 中】炼气 / 筑基按「攻」打不到正前方悬空的小怪
- **状态**：已复现（怪冻住、水平只隔 1.45 米、按 J 6 下命中 0 次）。
- **复现步骤**：炼气期进图，找「噬金虫 / 赤火蝠 / 鬼雾幽魂」（floater 型），贴到它身前按攻击。
- **预期**：怪就在正前方、看起来够得着时，主攻击能打到（或有明确提示 / 自动转成能打到的招式）。
- **实际**：噬金虫悬在地面上 2.20 米，地面近战竖直判定只有 1.3~1.7 米（`player_melee.gd:51-71` 的 `vreach`），6 下 0 命中、血量 22 → 22，没有任何反馈。
  floater 平时悬 2.2 米、追人时至少 1.5 米（`raid_mob.gd:807/837`），且是远程、保持 9 米距离。
  低境界能用的远程手段是飞剑阵（键盘 Q / 手机上附近有敌人时浮出的「阵」，`touch_controls.gd:118-120`），「剑 / 诀」要空战（结丹起）才有。
- **证据**：`logs/qacombat_floater_out.txt`；探索流程里另有两次「怪血 27 → 27」「32 → 32」打不动（`qaflow_bload_out.txt`、`qaflow_touch_out.txt`，当时没记怪的种类，疑似同一原因）；
  对照：同样站位打贴地的「草原妖狼」6/6 命中（`logs/qacombat_headless3_out.txt`）。
- **影响**：新手（手机玩家为主）面对飞虫类远程怪狂按「攻」没反应，容易误以为是 bug 或手感差；需要靠玩家自己发现「阵」。

### BUG-04【P2 中】联机受击时攻击来源找不到，`player_melee.gd:1069` 脚本报错：扣了血但没有受击反应，致命一击不触发陨落事件
- **状态**：已复现 3 次（真实入口 `raid_manager.net_take_hit(src=null)`）。
- **复现**：联机里地面状态下，被别人名下的怪打中而本机找不到它的木偶（木偶 1.5 秒收不到更新会自动回收，网络卡顿时就会出现），
  或被一个本机还没建出木偶的玩家打中。测试中直接调用 `net_take_hit(null, …)`。
- **预期**：照常受击（硬直、受击特效），致命时陨落。
- **实际**：`SCRIPT ERROR: Invalid call. Nonexistent function 'blade_tip' in base 'CharacterBody3D (Player)'`；气血 100 → 95.5 扣了，
  但近战状态没变成受击（仍是 1 / 8），后面的受击特效、`player_dead` 事件都没执行；致命时 `player.dead` 不置位，只靠大世界每帧的 `hp <= 0` 兜底结算。
- **证据**：`logs/qaflow_bload_err.txt`、`qaflow_touch_err.txt`（带完整调用栈 `net_take_hit → receive_attack → _on_hurt`）、`qaflow_bload_out.txt`。
- **原因**：`raid_manager.gd:757` 来源无效时回退成 `player` 自己，而 `player_melee.gd:1069` 无条件调用 `src.blade_tip()`，Player 没有这个方法。

### BUG-05【P2 中】高境界瞬移（瞬身追击 / 坠星踏 / 冲拳缩地）时镜头一帧跳 25~31 米

## 6. 未覆盖范围

- **真机**：没有手机 / 平板真机；触屏结论来自 `--touch` 模拟（桌面上鼠标 / 注入触点当手指）、兼容渲染器手机画质档和桌面无界面 Edge。
  iOS Safari、安卓 Chrome、真实触摸手感、发热降频、刘海 / 安全区、横竖屏切换、后台切换都没测。
- **多人**：只在一台机器上用多个进程走 127.0.0.1；**没有跨机器局域网、没有延迟 / 丢包 / 抖动模拟、没有 4 人以上**；
  网页 / 手机版本身没有真人联机（`main.gd:883` `_matchmake` 在 web 上直接单人进、AI 补位），所以「手机多人」不存在可测对象。
  联机下的 BUG-01（局内洞府）、断线重连、房主在主城当服务器时再入境、两人绕圈数不同的循环世界换像没有专门测。
- **人工试玩**：所有输入都是脚本发的；手感、可读性、新手引导、界面美观没有人工评估。
- **长时间**：没有实时跑满 20 分钟一局（禁地封闭靠快进验证），没有连续数小时的内存 / 发热测试。
- **性能结论**：测试期间机器上同时有用户的两个游戏窗口和并行测试，帧耗时只作参考。
- **音频真实出声**：网页版需要用户手势才能出声，无界面浏览器里没法验证（原生端见第二批音频自检）。
- **BUG-01 的联机变体**：联机局里打开洞府（游戏暂停）对房间里其他人的影响没测。
