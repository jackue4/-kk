# 侦察：用方块世界做两张新的有边界关卡（沙漠 + 地道 / 研究所）

只读调研，引用的行号都是 2026-11-24 工作区里的样子（别的会话还在改 block_world.gd，动手前再核一遍）。

## 0. 结论速览

- `block_world.gd` 本质是**单层高度表**：2 米一格、1 米一级，每格一个顶面高度，侧面是邻格之间的落差；没有真的洞和悬空。地形**不建物理碰撞体**，人踩 `height()`，再叠一层「实心盒子」（`solid_h`）当台基 / 墙 / 屋顶。
- 循环（3456 米一圈）是**写死在常量里的**（`Data.HALF / Data.LOOP` 散在十几处），但对**整张图离原点不超过 ±1700 米**、人又被边界框住的地图来说，`wrapf / posmod / near()` 全是恒等变换。**新图第一阶段不用拆循环**，换掉「地形内容」就行。
- 推荐做法：新写一个**数据驱动的网格世界** `grid_world.gd`（继承 block_world.gd，只覆盖取样 / 配色 / 摆件这几个函数，网格生成、分块调度、实心盒子、破坏、小地图取样全复用）＋ 一张地图定义表 `map_def.gd`。两张图的高度 / 地表 / 建筑清单都是**离线烘好的数组**，运行时查表，比现在的噪声取样快得多。
- 沙漠的地下层：推荐**两份高度表叠放**（地面一份、地道一份，地道整体压到 -60 米），`ground(x, z, y)` 按 y 分流；地道层单独一套材质 / 光照层。退路是把地道放到远处的另一片坐标、竖井口传送过去。
- 研究所「能进的楼」：现有实心盒子已经能走「多层楼 + 楼梯 + 从屋檐下过」，**缺的是**：飞行 / 跳跃不撞墙不撞顶、镜头只认二维高度、怪和 AI 不认盒子、盒子只在主角身边 3×3 块里登记。这四项是研究所能不能玩的前提。
- 边界：别用看不见的墙。沙漠 = 一圈高崖台 + 沙暴带（浓雾 + 推回 + 掉血，夹钳藏在看不见的地方）；研究所 = 高围墙 / 断崖 + 看得见的禁制光幕。两张图都要压飞行高度。
- 性能：手机网页现在的大世界是 162~215 次绘制、145~207k 图元、31~49 块细地块；新图照这个量级定预算（见 §3）。
- 小地图：现在是围着主角现算的 48×48（网页 28×28）小图；有边界的图应该**载入时一次烘整张图**，圆形小地图和全屏大地图都从这张图上取。

## 1. block_world.gd 的数据模型和 API

### 1.1 尺度、分块、精度

- `CELL = 2.0`（格宽）、`STEP = 1.0`（台阶高）、`CHUNK = 96.0`（一块地）、`N = 48`（一块 48×48 格），`scripts/block_world.gd:37-40`。
- 三档精度：
  - **细地块 lod0**：2 米格，投影，记实心盒子；主角周围 `near_r = 1` 圈（切比雪夫距离，3×3 块）（`_plan`，`:1193-1232`；`_apply` 里 lod0 才开投影，`:1284`）。
  - **粗地块 lod1**：6 米格、16×16、不投影，铺到 `view_r` 圈（`_build`，`:1563-1564`）。
  - **远景色块**：每块只切 `_far_n × _far_n` 格（多线程 8 = 12 米，单线程 6 = 16 米），主线程随手建，铺到 `far_r` 圈（`:1302-1511`）。
- 圈数（`_ready`，`:278-290`）：桌面 `view_r 6 / far_r 8`；手机 `view_r 4 / far_r 6`；单线程网页（`_sliced`）`view_r 3 / far_r 6 / _far_n 6`。
- 调度在 `_process`（`:1077-1181`）。按速度预判前方（`LEAD_T 2.2 / LEAD_REAL_T 1.4`），飞得比 `FAST_SPD = 50` 快时只补粗的（`:100-102`）。
  - 有线程：丢 `job_pool.gd`，同时最多 `MAX_JOBS = 2` 块（`:57`）。
  - 网页单线程：`_build` 里有让出点，每帧 `SLICE_US = 7000` 微秒，按掉帧自动收放（`:120-136`、`:1118-1157`）；进图黑屏时关卡调到 45000（`meadow_level.gd` `prewarm`）。

### 1.2 高度怎么来

取样链是 `_raw → _shaped → _cell → height`：

- `_raw(x, z)`（`:508-576`）：先把坐标折回 `[-HALF, HALF)`，按半径 / 扇区选地貌函数（`_h_meadow / _h_canyon / _h_ruin / _h_karst / _h_fall`，`:386-498`）。依次叠上：
  - 道路（`_road`，路面盖过地形，高的是桥、低的是路堑）；
  - 地标台子（`_ax/_az/_ar/_ah`）；
  - 外海下沉；
  - 孤岩。
- 地貌函数的积木是 FastNoiseLite（`_hills / _mid / _ridge / _peaks / _cl`，`_init` 里 `:199-226`），加上一个「抖动特征点网格」`_feat(x, z, g, salt)`（`:326-350`，石柱 / 方山 / 碎台的中心）。
- `_shaped`（`:579-589`）：再按 `_pois` 压平地标那一圈。
- `_cell(ix, iz, cs, dug)`（`:650-694`）返回 `[顶面高度, 区域 ri, 是不是低处填充, 是不是地标石板地, 地表种类 K_*]`。这是**网格生成唯一要的格子信息**，新地图只要换掉它就能复用整个网格生成器。
  - 地表种类：`K_PATH / K_POOL / K_RIM / K_PUDDLE / K_ROAD / K_ROAD_EDGE`（`:46-51`）。
  - 低于 `CLOUD_Y = 0` 的格子是「低处填充」（海 / 河 / 血河 / 云海 / 魔雾），顶面换成 `_cloud_top`（`:625-646`）。
- `height(x, z)`（`:704-719`）是玩法用的地面：取格子中心的 `_shaped` 取整，被炸过的取 `_dug` 里的上限；低处填充再减 `LIQUID_SINK[ri]`（`:700`，海 / 河 / 云海陷 0.6 米，坠魔谷 0）。
- 路网 `_build_roads`（`:1984-2065`）：一串带两头高度的线段，按 64 米格建索引（`_rgrid / _rflag`，64×64，覆盖 ±2048 米）。地标索引 `_pgrid` 是 128 米格、32×32（`:78`、`:268-274`）。两张索引表都只覆盖 ±2048 米，新图在这个范围内够用。

### 1.3 网格生成

- `_build(key, lod)`（`:1559-1606`）的流程：
  1. 先把 `(n+2)²` 个格子的 `_cell` 算进 `hs / rg / fl` 三张表（多一圈是为了知道邻格高度）；
  2. 收集自己和八个邻块的灯火 `_lights`（`:1529-1547`，烘成假点光）；
  3. 逐行调 `_mesh_row`（`:1729-1896`）：每格一个顶面四边形（四角按邻格遮挡压暗，`AO`，`:52`），加上比邻格高出来的侧面（按岩层 `band` 分段上色、崖顶一米土、墙根压暗）；
  4. 拼点缀物 `_wall_props / _falls / _props`；
  5. `_compose` 合成一个 ArrayMesh（`:1635-1656`）。
- **一块地 = 一个网格 = 一次绘制调用**，材质共用一个 `mat`（block_world.gdshader）。
- 炸坑后的重建走 `_rebuild`（`:1661-1725`）：用缓存的中间结果，只重做受影响的几行。

### 1.4 建筑 / 点缀 / 地下

- 构件库都是往 `a = [顶点, 法线, 顶点色, 索引(, 实心盒子)]` 里拼方块：
  - 基础：`_box(a, size, xf, c, em, shade)`（`:2306-2341`，**不画底面**，`fi == 3` 跳过）、`_xf`（`:2348`）。
  - 成组的：`_roof / _hall / _ring_wall / _colonnade / _obelisk / _bridge / _arcade / _paifang`（`:2083`、`:2728-2862`），以及文件末尾的 `_town / _giant_gate / _seal_gate / _statue / _falls / _boat / _water_wheel` 等（`:3137-3404`）。
  - 地标建筑先按原尺寸摆、再用 `_scale_from` 放大，实心盒子跟着放大（`:3408-3425`）。
  - 配色 `STYLES`（`:2715-2724`，每套是 [墙, 梁柱, 瓦, 台基]）。
- 摆放：
  - `_props`（`:2352-2487`）：每块 34 个随机点，按区域分种类，`near` 时才放小件；
  - `_structures`（`:2506-2710`）：按地标和特征点摆成组的建筑；
  - `_road_props`（`:2096-2169`）：护栏、桥墩、拱洞、路灯、牌坊。
- **地下 / 洞**：高度表做不了。现在的「洞窟」`_arcade` 只是贴在崖壁上的深色方块（`:2845-2862`），桥下的「拱洞」也是深色块（`:2141-2162`）。memory `meadow-ghibli-art` 也写明「做不了真的洞和悬空」。

### 1.5 碰撞和落脚

- **没有地形碰撞体**。关卡在主角脚下垫一块跟着走的 6×2×6 `StaticBody3D`（`meadow_level.gd:244-250`），每个物理帧摆到脚下高度。
- 主角的落脚和挡路（`meadow_level.gd`）：
  - `_fl / _fl_own`（`:584-598`）= `max(height, solid_h(...))`；
  - `_walk_h / _ramp / _solid_ramp`（`:603-668`）：台阶走缓坡，`RAMP_MAX 1.5`；
  - `_clip_move`（`:671-693`）：撞高墙沿墙滑；
  - `_block_floor`（`:696-771`）：翻沿、低境界飞行贴山壁升、结丹以上 `_dig_through` 破山。
  - 规矩：`STEP_UP = 2.25`（`:63`）以内是台阶、更高是墙；`BODY_HEAD = 1.6`、`AIR_TOP = 0.6`（`:579-580`）。
- **实心盒子**（`block_world.gd:882-1007`）：
  - `_box` 在数组带第五项时（只有 lod0，`:1598-1600`）记一条 OBB；条件见 `:2335`：高 ≥ 0.12、最窄 ≥ 0.3、最长 ≥ 0.6、基本直立。软的东西用 `_sol_mark / _sol_cut` 包起来不记（`:897-906`）。
  - 生成线程里 `_sol_pack` 按 `SOL_CELL = 4` 米分格（`:910-932`）；落地时 `_sol_put`、撤块时 `_sol_drop`（`:935-969`）。
  - 查询 `solid_h(x, z, below, top_max)`（`:973-989`，只算底面低于 `below`、顶面不高于 `top_max` 的盒子）和 `solid_any`（`:993-998`）。实测每次 1.2~1.8 微秒。
  - 这条规矩天然支持「底面高过头顶的盒子从底下过、站到上面就是地面」，也就是多层楼板 / 屋檐。
- **已知缺口**（新图要补）：
  1. 飞行 / 空战只接比脚面高不出 0.6 米的顶面（`_fl_own` 的 airborne 分支，`:596-597`），**照旧能穿墙、穿楼板**；
  2. 没有「天花板」夹钳，跳起来头能穿过楼板，再落到楼上；
  3. 怪、AI、镜头只认 `floor_fn(x, z)` 二维高度：`raid_mob.gd:595`、`air_foe.gd:1489/1542/1623/1640/2033`、`ally_brain.gd:125`、`camera_rig.gd:528/548`；这些 `floor_fn` 在 `raid_manager.gd:689/1552/1986/2119` 赋值；
  4. 盒子只在 lod0 的 3×3 块里有，远处的 AI 问不到。

### 1.6 破坏

- `dig()`（`:724-743`）：飞进山体时削出通道。
- `crater_changes()`（`:752-790`）：炸碗形坑，`MAX_DIG = 9`，地标石板地不炸。
- 两者都写进 `_dug`（2 米格 → 高度上限），整表替换（`apply_dug`，`:838-858`）。联机由 net.gd 同步：`net.gd:308/345` 发整表、`:667` 远端挖。
- 研究所的墙、地道的岩壁要**关掉破坏**（至少关掉 `_dig_through`，`meadow_level.gd:551`），否则一飞就穿关卡设计。沙漠地表可以留炸坑。

### 1.7 颜色和网页端

- 顶点色存 **sRGB、8 位、不能超过 1**（`_pal` 的注释 `:255`；`_box` 和 `_mesh_row` 里都 `minf(...,1.0)`）；alpha 通道当自发光强度。
- 着色器 `shaders/block_world.gdshader`：
  - 兼容渲染器分支（`:51-54`）直接 `ALBEDO = c * pow(k, 0.4545)`，桌面分支先 `pow(c, 2.2)`（`:61`）。所以**并进地块网格的颜色不用转**（`_lin` 是恒等，`:2344`）。
  - 另有半球补光 / 补光 uniform（`hemi_sky / hemi_ground / fill_col / fill_dir`，`:14-17`），由 `raid_manager.gd:1284-1293` 按区域设。
- 别的材质（StandardMaterial3D 的顶点色、实例色）要过 `MeshLib.vcol()`（`mesh_lib.gd:16-19`），见 memory `web-renderer-color-space`。
- 兼容渲染器的主光要乘 `COMPAT_SUN_K = 0.11`（`raid_manager.gd:219/1259`）。
- 调色表 `look.gd`：24³ LUT 挂在 `Environment.adjustment_color_correction`，`Look.apply` 在 `BlockWorld.make_environment()` 末尾调（`block_world.gd:175`），新图共用、不用另做。
- 区域的天色 / 雾 / 环境光在 `raid_data.gd` 的 `REGIONS`（`:48-92`），可读性参数在 `LOOK`（`:103-114`）。`raid_manager._blend_atmosphere` 按 `Data.region_weights`（`raid_manager.gd:1117-1119`，`raid_data.gd:286-304`，按半径 / 扇区算）渐变。**新图要换成自己的区域权重**，比如按 y 区分地面 / 地下，按格子区分楼内 / 楼外。
- 区域序号 0..4 还写死在 block_world 的几张常量表和判断里：
  - 常量表：`SHADE`（`:55`）、`SEA_Y`（`:117`）、`LIQUID_SINK`（`:700`）、`LIQUID_EM`（`:2193`）；
  - 循环：`_process` 里 `for i in 5`（`:1097`）；
  - 判断：`_mesh_row` 的 `dim = ri == 2 or ri == 4`、`ri <= 1` 水沫（`:1749`、`:1766`），`_wall_props` 的 `ri > 2` 跳过（`:2874`），`_falls` 的 `ri == 2/4`（`:3384-3392`）。

### 1.8 其他几个文件

- `meadow_gen.gd / meadow_terrain.gd / ghibli_kit.gd`：老的吉卜力草原，只剩 `--meadow-shot` 自检在用（`meadow_level.gd:1-14`）。256 米块、四档精度，**用 ConcavePolygonShape3D 建碰撞**（`meadow_terrain.gd:401-409`），还有草叶 / 花。和方块画风不搭，**不建议复用**，只有 `JobPool` 的用法可以参考。
- `test_hall.gd`：灰白测试场。`WorldBoundaryShape3D` 地面（`:161-172`）、四面 320 米高不画碰撞的墙（`:418-423`）、Boss 圈 `BOSS_R`。`boss_arena.gd`：「进赤线 TRIGGER_R 开打 / 跑出 LEAVE_R 脱战」的圆形触发写法（`:19-20`），可以照搬给新图的 Boss 区 / 撤离区。
- `hub_hall.gd` 是**现成的「有边界的静态方块图」样板**：
  - 数据：`N = 180` 格 × 2 米（360 米见方），高度表 `_h`、地表 `_t`、实心格 `_solid`、细盒子 `_fine`（`:57-58`、`:99-101`、`:322-324`）；
  - 写入：`_put / _rect / _disc / _block / _block_fine`（`:287-324`）；
  - 网格：地面一张、建筑一张，各一次 `_commit`（`:511-570`）；
  - 落脚：`_physics_process`，掉出岛外送回入口（`:1305-1365`）；
  - 镜头：`occl_fn = _cam_block_h`（`:239-240`）。
  - 实测：地面 58,256 顶点、建筑点缀约 51k 顶点，主城 101~133 次绘制。它借 `BlockWorld._box` 和配色（`:102`、`:151`）。
  - 缺点：整张一个网格，没有视锥裁剪、没有 LOD。**到 512×1024 就不能这么做**。

## 2. 循环是不是写死的？两张新图怎么做

### 2.1 循环写在哪

- **block_world.gd**：
  - 坐标折回：`_raw :509-510`、`_shaped :580-581`、`_region :600-601`、`_cloud_top :630-631`、`_cell :652-654`、`height :705-706`、`_road :1945-1946`；
  - 外海：`_raw :568-572`、`_region :607`；
  - 地块编号折回 / 平移：`_wk :877-879`、`_img_off :1010-1012`、`_img_key :1016-1018`、`_wc :1022-1024`（其中 `_wk / _img_off / _wc` 是 static，子类覆盖不了）。
- **调用方**：
  - `raid_manager.gd`：地标换像 `Data.near`（`:672/703/777/994/1000/1868/2787`、`_reimage :1571`）；海上不刷怪 `land_r`（`:1773/1780/1814/2023/2605`）；出海题字 `at_sea`（`:1327`）；魔气漩涡 `near(-1090,0,0)`（`:1312`）。
  - `raid_camps.gd:90/238/247/263/296/307/450/474/479`、`raid_search.gd:143`、`net.gd:493/539/571/634`、`ally_team.gd:94`。
  - 主角放开边界：`meadow_level.gd:264` `player.bound = 1.0e9`。
- **对小图是透明的**：
  - `wrapf(x, -1728, 1728)` 对 |x| < 1728 是恒等；
  - `Data.near(base, ref)` 在两点相距不到 1728 米时返回 base 本身；
  - `land_r` 在原点附近 ±700 米内永远小于 `PLAY_R = 1450`，「海上」判断永远不成立。
- 所以只要地图**以原点为中心、半边不超过约 700 米**，再给主角上个矩形边界：循环这层不用动；破坏表、联机换像也照常工作。512×1024 半边是 512，够用。

### 2.2 推荐：数据驱动的网格世界

**新文件：**

1. `scripts/map_def.gd`（静态数据，不 class_name）：`MAPS = {"desert": {...}, "lab": {...}}`。每张图一条，内容是：
   - 尺寸 / 原点、格子数据文件路径；
   - 自己的 `regions`（和 `Data.REGIONS` 同样的键：top / stone / water / sky / fog / amb / sun / light…）、`look` 表；
   - 出生点 / 撤离点 / Boss 区 / 搜点 / 钥匙房 / 刷怪点列表；
   - 边界类型、飞行高度上限、地下层参数。
2. `assets/maps/<id>/`：离线烘好的格子数据。
   - 每层 `u16` 高度（0.5 米精度）+ `u8` 地表种类 + `u8` 区域 / 风格；
   - 楼宇清单 `boxes.bin`（每个盒子 中心 / 尺寸 / 朝向 / 颜色 / 是否实心 / 是否屋顶层）。
   - 体积：沙漠 256×256 格 ≈ 256 KB/层，研究所 256×512 格 ≈ 512 KB。
   - 生成工具放 `_tasks/maps/`（Python 或 `-s` 跑的 GDScript）。DarkArea 那边**没有方块存档**（只有 Lua 里的区域坐标，见 §2.7），所以布局要按它的区域坐标 + 截图重新摆。
3. `scripts/grid_world.gd`：`extends "res://scripts/block_world.gd"`（项目不用 class_name，用路径继承）。
   - **覆盖**：`_cell`（查表）、`_shaped / _raw`（查表，给 `map_cells`、`crater_changes`、`_gy` 用）、`_region`、`_top_color / _wall_color / _cloud_color / _masonry`、`_lights`、`_props / _structures / _road_props / _town / _wall_props / _falls`（按楼宇清单逐块摆，或者留空）、`has_land`。

### 2.3 沙漠：地面 + 地下 -60 米两层

**推荐 A：两份高度表叠放，按 y 分流。**

**两个世界实例**（都是 `grid_world`）：

- **`surface`**：沙丘、戈壁、遗迹。竖井口的格子高度直接落到 -60（地面网格自己就会画出 60 米深的井壁）；斜坡道是一条一路往下的路堑。
- **`tunnel`**：整体在 -60 米上下。通道格的高度 = 地道地面；岩体格的高度 = 顶板高度（只画侧面、不画顶面，在 `_mesh_row` 里给一个「岩体」标志跳过顶面）。另加一遍「顶板」：每个通道格在顶板高度补一个朝下的四边形（`_box` 不画底面，要单写）。
- 竖井和坡道段的格子在两份表里**数值一致**，人从一层到另一层是连续的。

**分流规则**：`level.ground(x, z, y := INF)`，`y < LAYER_SPLIT`（比如 -25）问 `tunnel`，否则问 `surface`。

- 只传两个参数的老调用方默认问地面，不会坏。
- 要改的调用点（怪 / AI / 镜头传自己的 y）：
  - `raid_mob.gd:596`；
  - `air_foe.gd:1489/1542/1623/1640/2033`；
  - `ally_brain.gd:125`；
  - `air_melee.gd:893`；
  - `camera_rig.gd:528/548/568/585`；
  - `yuanying_cine.gd:138/265/404`；
  - `raid_manager._ground / _on_ground`（`:319-324`，刷怪 / 掉落带上层号）。

**顶板夹钳**：地道里主角 / 怪的 y 不能超过 `顶板 - 身高`。`player.gd` 现在只有按境界的相对飞行上限（`:1199-1205`，`ceiling + ground_ref`），要加一个绝对上限 `ceil_abs`，由关卡每帧给。TSB 式的击飞在地道里会被顶板吃掉，打法要按这个设计。

**渲染**：

- 地道网格放到单独的渲染层（`VisualInstance3D.layers = 2`），主光 `light_cull_mask` 不含这一层，地下就不会被阳光照亮。
- 地道世界用自己的一份 `ShaderMaterial`，压低 `hemi_sky / hemi_ground`，靠 `_lights()` 烘的火把光池 + 自发光晶体出氛围（不加实时灯）。
- 人在地下、离竖井 40 米以外时，`surface.visible = false`，在地面时 `tunnel.visible = false`，省一半绘制和阴影；靠近竖井两边都显示。
- 雾和天色走「地下」这个伪区域；镜头远裁在地下可以降到 200 米上下。
- 地道世界关掉远景色块和粗地块：`far_r = 0`，`view_r` 小一点。

**退路 B**：地道放到远处另一片坐标（比如 x +1200），竖井口做「入井 → 黑场 → 传送」。

- 好处：**所有 `floor_fn(x, z)` 调用方一行不用改**，联机位置也只是坐标。
- 代价：「就在脚下 60 米」的空间感没了；放远了还要防远景色块被看见（`far_r × 96` ≈ 576~768 米，加雾挡住）。

**不推荐 C**：用实心盒子当整片顶板。盒子只在 lod0 记；怪 / AI 不认；整片顶板的盒子数会很多。只适合局部的悬挑、桥洞。

### 2.4 研究所：很多能进的楼

楼的搭法照现有规矩：

- 墙 = 实心盒子（顶高过 `STEP_UP` 就是墙）；
- 楼板 = 底面高过「脚面 + 1.6」的盒子（楼下的人从底下过，楼上的人站在顶上）；
- 楼梯 = 每级 ≤ 2.25 米、宽 ≥ 0.6 的盒子（`_solid_ramp` 会走成缓坡）；
- 门洞：block_world 的盒子是按真实 OBB 记的（不是主城那种两米一格），门洞宽多少就能过多少。

层高建议 ≥ 4.5 米、门宽 ≥ 3.5 米：主角是粗壮方块人，TSB 打法要横向空间。

**必须补的四项：**

1. **空中也要撞墙、撞顶**：`_fl_own` 的 airborne 分支加 `_clip_move` 式的墙判定；再新加 `ceil_h(x, z, y)`（头顶上方最近的盒子底面），给跳跃 / 飞行 / 击飞夹顶。
2. **镜头三维遮挡**：现在 `occl_fn(x, z)` 返回的是「这一格最高处」（`camera_rig.gd:544-599`），在有屋顶的楼里会一直把镜头收到 `OCCL_MIN`。要换成 `occl3(p: Vector3) -> bool`，判断点在不在盒子里或者地下。
3. **怪 / AI 认盒子**：给它们一个 `walk_h(x, z, y)` 和 `blocked(from, to, y)`。
4. **盒子全图静态登记**：载入时把整张图的楼宇清单一次登记进 `_scells`（4 米格），不跟着 lod0 走；现在的登记在 `_build` 的 lod0 分支里，`:1598`。研究所约 40 栋楼、几千个盒子，内存几百 KB，查询还是 1~2 微秒。

**屋顶剥离**：人进楼后，挡住镜头的屋顶和楼上要藏起来。

- 建议每块地把「屋顶 / 楼上」单拼成第二个网格：同一个着色器的一个变体，`cut_on` 时在主角周围半径内、主角头顶以上的片元 `discard`。
- 只给屋顶网格用这个变体：`discard` 会关掉移动端 GPU 的提前深度测试，别加在地面那张网格上。
- 代价是有楼的块多一次绘制。

**粗地块**里的楼只画外壳，不画室内家具（`_props` 已有 `near := lod == 0` 的写法，`:2355`）。

### 2.5 边界：别做空气墙

用户在循环世界里明确不要空气墙（memory `loop-world`），但搜打撤的图本来就有边（DarkArea 用区域框踢人，出区罚 5000 币：`DarkAreaFightMgr.lua` 的 `zoneAreaPos / leavePunishCoin`）。做法是**让边界看得见、讲得通**，硬夹钳藏在看不见的地方。

- **沙漠**：

  - 再压一个全图的绝对飞行上限，比崖顶高出一截就停，防止飞越。
  - 低处可以做流沙（低处填充 + `LIQUID_SINK`）。
- **地道**：岩壁本身就是边，加顶板夹钳。
- **研究所**：
  - 外圈 15~20 米的高围墙 / 断崖（高度表）。

- 飘浮物手机 40 个（`meadow_level.gd:281`）；
- 着色器里铺满屏的东西查贴图、不现算噪声，并进 `warmup.gd` 预热（memory `mobile-fullscreen-shader-cost`）。

**新图的预算建议**（网页档同一探针）：

- 绘制调用 ≤ 220：地面 / 地道各一个世界时，按显隐只开一个；屋顶网格每个有楼的块 +1。
- 图元 ≤ 220k。

- 新的大面片着色器（沙暴、光幕）单项不超过天幕（`quad_bench` 的 0.30 ms 那档），手机档用查表噪声，并进 `warmup.gd`。
