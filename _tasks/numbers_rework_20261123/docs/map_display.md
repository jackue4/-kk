**Hammer 的写法**（`H:/Hammer/Project/logic/lua/HammerUtils.lua:325-340` `Utils:FormatNumberText`）：单位表是 `{"", "万", "亿", "兆", "京", …}`，每满一万进一个单位，然后 `string.format("%.4g", n) .. unit`，也就是**统一保留 4 位有效数字、去掉末尾的 0**（「1.234万」「12.34万」「1234万」「1.2亿」）。Hammer 的战力面板另有一套分整数 / 小数 / 单位的版本（`HammerUIBattleValue.lua:164-210`），用来拼美术字。
⚠ **GDScript 的 `%` 格式化不支持 `%g`**（只支持 s c d o x X f v），4 位有效数字要自己算小数位数（`"%.*f" % [prec, x]`，或者 `String.num(x, prec)`），再去掉末尾的 0。

**建议**：新建一个没有任何依赖的 `scripts/num_fmt.gd`（按项目惯例不写 class_name，用 preload 引用），提供 `num(v)`（Hammer 的 4 位有效数字，单位用 万 / 亿 / 兆）和 `int_or_num(v)`（小于一万写整数）两个函数，然后把 `Prog.short_num` / `_num` / `_num1` / 行内那几处都改成调它。`vfx.gd` 也可以直接 preload 它（`vfx.gd` 是 `class_name Vfx`，现在只 preload 着色器和几个特效脚本；`progression.gd` 只 preload `raid_data.gd`，而 `raid_data.gd` 一个 preload 都没有，所以哪个方向都不会成环）。

## 2. 3D 伤害飘字 `Vfx.damage_number` 和全部调用点

`scripts/vfx.gd:362-385`：
```gdscript
static func damage_number(pos: Vector3, value: float, color: Color) -> void:
	if mute >= 2:
		return
	var l := Label3D.new()
	l.text = str(int(round(value)))
	l.font = font
	l.font_size = 56
	l.pixel_size = 0.008
	l.outline_size = 14
```
- 每一下都新建一个 Label3D 加一个补间动画，**没有对象池，也没有限流**（`lite` 档只限制了 `hit()`，`vfx.gd:355`）。高境界连发每秒几十柄剑，数字一长，每个字一个面片，手机上的开销也跟着涨；短写反而能省。
- `font_size 56` × `pixel_size 0.008`：每个数字在世界里大约 0.25 米宽，9 位数大约 2.3 米宽。
- `value < 0.5` 时写成 "0"（现在天道压制 0.55^差距 时会出现 0 / 1）。
- 字体 `Vfx.font`：Windows 上是系统楷体（`main.gd:126-131`），网页 / 手机上是 `UiStyle.kai()`，也就是随包正文字体加补字后备（`main.gd:133-134`）。
- 字形预热：`warmup.gd:304-305` 只拿 `1234567890.0` 和 `88.0` 预热过（这种 Label3D 的字形缓存按「字号 56 / 描边 14」单独存），**没有预热「.」「万」「亿」**。改成短写以后，第一次飘「万」会现画字形，手机上会顿一下。另外 `warmup` 只在触屏 / 网页上跑（`main.gd:117`）。

## 5. 战力

**现有公式** `combat_stats.gd:182-188`：
```gdscript
static func power(realm: int, lv: int, fx: Dictionary) -> int:
	var a := atk(lv) * (1.0 + minf(float(fx.get("atk", 0.0)), GEAR_ATK_CAP)) * 10.0
	var d := hp(lv) / maxf(1.0 - float(fx.get("guard", 0.0)), 0.4) * (1.0 + 0.2 * float(fx.get("vital", 0.0)))
	return int(round((a + d) * pow(1.1, float(clampi(realm, 0, MAX_REALM))) * (1.0 + 0.05 * float(fx.get("seek", 0.0)))))
```
- 取值：炼气 1 级 230；`combat_table.md` 第 4-12 行「战力（无法宝）」那一列是 287 / 504 / 761 / 1065 / 1422 / 1839 / 2326 / 2892，大乘 40 级 4780；99 级戴满法宝约 2.5 万。
- 调用方：`player_plate.gd:57-58`（`power()` 只是转一手）、`279`、`289`；`_tasks/numbers_sim/combat_table.gd:47,69`（「战力（无法宝）」那一列）；主工程 `_tasks/ui_kit/plate_test.gd:32,39`。
- `fx` 字典的键是 `atk / guard / seek / vital`，值是比例，来自 `Items.fx_total`（`raid_items.gd:173-181`，守封顶 0.6、攻封顶 0.8）。法宝要是改成固定数值、按品阶 ×1.65，`fx_total` 的返回结构和 `power()` 的参数都要一起改。

## 13. 字体（网页 / 手机上会不会变成方块）

**字体链**（`ui_style.gd:34-100`）：
- Windows 桌面：系统楷体 / 行楷（`main.gd:126-131` 给 Vfx 和界面；`ui_style.gd:88-100` 的题字用 `BRUSH_FILES`），字全，不会缺字。
- 网页 / 手机：正文是 `assets/fonts/NotoSansSC-Medium.subset.otf`，后备是补字字体 `SourceHanSansCN-Normal.patch.ttf`；题字是 `SourceHanSerifSC-Heavy.subset.ttf`，后备是正文，再后备是补字字体（`ui_style.gd:55-70`）。`realm_banner._load_font()`（`realm_banner.gd:61-66`）在非 Windows 上直接 `load` 题字字体，和 `UiStyle` 是同一份资源，后备链是 `UiStyle.kai()` 第一次调用时挂上的（`ui_style.gd:77-78`）。`combat_word` 也用这个字体。
- **`project.godot` 没有设默认字体**（搜不到 theme 或 font）：新建的 Label 要是没挂在设过 `default_font` 的主题下面（hud 根节点、玩家牌、raid_hud 的 `_root` 都设了），也没有单独指定字体，在网页上就全是方块。做「战力 +N」小字时要注意这一点。

**`_tasks/ui_kit/font_check.py`（只在主工程里有）**：
- 用法：`python -I _tasks/ui_kit/font_check.py` 只核对，结果写到 `_shots/font_check.txt`（UTF-8）；`python -I _tasks/ui_kit/font_check.py --patch` 从本机的 `C:/Windows/Fonts/SourceHanSansCN-Normal.ttf` 把缺的字裁进补字字体，之后要用 Godot `--import` 一遍。导出网页版之前要跑（记忆里的 web-mobile-deploy 记过）。
- 扫的范围：**只扫 `scripts/*.gd` 里字符串字面量用到的字**（注释不算，`lit_chars` 在 `27-49` 行），而且只看码位大于 0x2000 的字。所以：① 数字、「.」「+」「/」「%」这些 ASCII 字符不检查（现在能正常显示，说明子集里有）；② 只出现在注释里、运行时拼出来的、或者写在 JSON / 数据文件里的字，它都查不到 → 单位表一定要写成脚本里的字面量，例如 `const UNITS := ["", "万", "亿", "兆"]`。
- 它只判断**正文字体**缺不缺（`60` 行 `need = … not in body`），**不检查题字字体缺的字**（`78-79` 行只列出「题字字体没有、正文有」的字）。仓库里也**没有重新裁正文 / 题字子集的脚本**（只有补字这一个）。

## 16. 隐藏的假设（容易漏）

1. `player.melee.hp` 永远是 0 ~ 100 的条；所有「气血 +N」的治疗（丹药 25 / 30 / 35 / 60、升级 +20 见 `raid_manager.gd:435`、`raid_manager.gd:938` 的 `maxf(hp, 30.0)`）都是条上的点数，玩家牌显示的却是真实气血。
2. `raid_hud.gd:665` 把区域的怪等级和主角的修为等级放在同一个刻度上比。
3. `Vfx.damage_number` 先四舍五入成整数；没有暴击 / 颜色分档（只有重击金色 `Color(1.0, 0.85, 0.5)`、刀客红色）。要加暴击的话，在这里加字号 / 颜色。
4. `CS.power` 返回 int，玩家牌直接 `str()` 不格式化；GDScript 的 int 是 64 位，到「兆」也不会溢出，但显示必须短写。
5. 联机同步伤害用的是 RPC 浮点（`net.gd:799-803`、`815`，Variant 浮点是 64 位），数变大不会被截断。存档里的修为是浮点（`raid_profile.gd:100`），灵石是 int；数变大，JSON 也存得下。
6. 修为丹存档里的 `name`（带品质前缀）和 `exp` 是旧值：显示药力一律现算，名字不会现算。
7. `Prog.short_num` 的 4 个调用方（hall_pills、hub_hall、raid_hud、raid_items、raid_manager）都假设它返回的串够短（放在提示和按钮里）；改成 4 位有效数字以后长度差不多，换成「兆」也不会变长。
8. 「心得 +N」小于一万时写整数、最少写 1——这条规则写了两份（`insight_fx.gd:330`、`raid_hud.gd:620`）。
